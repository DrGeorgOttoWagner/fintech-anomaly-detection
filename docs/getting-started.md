# Getting started

## Requirements

FTAD v1.0.0 supports **macOS only** (tested on macOS / Apple Silicon, Apple M3 Pro).

| Requirement | Install |
|---|---|
| [Homebrew](https://brew.sh) | see brew.sh |
| Python 3.12+ | `brew install python@3.12` |
| Node.js 20+ | `brew install node` |
| OpenMP runtime (XGBoost, LightGBM) | `brew install libomp` |

## Install

```bash
git clone https://github.com/DrGeorgOttoWagner/fintech-anomaly-detection.git
cd fintech-anomaly-detection
./scripts/setup.sh
```

`setup.sh` does the following:

1. Creates `backend/.venv`.
2. Installs the pinned backend dependencies (`backend/requirements.lock`) and FTAD itself.
3. Installs the frontend dependencies (`npm ci`) and builds the UI.
4. Copies `.env.example` to `.env` if no `.env` exists.

It stops with a message on any operating system other than macOS.

## Start

```bash
./scripts/start.sh
```

Open **http://127.0.0.1:8790**. The server listens on the loopback interface only. Stop it with `Ctrl+C`.

For development with hot reload (API on :8790, Vite UI on :5173):

```bash
./scripts/dev.sh
```

## Configuration (`.env`)

| Variable | Default | Meaning |
|---|---|---|
| `FTAD_HOST` | `127.0.0.1` | Bind address. Keep loopback for local-only operation. |
| `FTAD_PORT` | `8790` | Port of the API and UI |
| `FTAD_DATA_DIR` | `./var` | Uploads, parsed datasets, experiments, reports and the SQLite registry |
| `FTAD_EXPORT_DIR` | *(empty)* | Optional folder for one-click report export (copied into `<dir>/ftad_exports/`) |
| `FTAD_MAX_UPLOAD_MB` | `1024` | Upload size limit |

## First run with the synthetic demo dataset

1. Start FTAD and open http://127.0.0.1:8790.
2. Click **Browse Files** and choose `demo/synthetic/synthetic_transactions.csv`.
3. On **Schema Mapping**, check the suggestions (`Class` → target, `Time` → time, `Amount` → numeric,
   `V1…V10` → existing PCA features), select positive label `1`, then click **Confirm schema**.
4. Open **Exploratory Analysis**, then run a **Quick Benchmark** in the **Experiment Studio**.

The synthetic data are generated by `demo/synthetic/generate_synthetic.py`. Results on them say
nothing about real fraud.

For a real-data study, follow the
[credit-card fraud showcase workflow](../examples/credit-card-fraud/workflow.md).

## Run the tests

```bash
./scripts/test.sh                       # backend pytest + frontend type-check + lint
cd frontend && npx playwright test      # browser acceptance workflow (synthetic fixture, own port and data dir)
```
